## What I changed, rejected or corrected

- **Rejected a paired per-draw comparison** the agent offered when frozen vs scratch was unresolvable at 50 and 100 labels. Choosing a sharper test after the prescribed one failed to confirm what theory predicts is motivated analysis; the brief fixes mean ± SD.
- **Overrode the run's mechanical verdict at 2,000 labels.** The incumbent's −0.6 "passed" my gap-vs-SD rule against an SD of 0.4, but all five runs at 2,000 use the same panels, so that SD omits which-panels variation. The memo reports it as indistinguishable from noise.
- **Caught a contradiction in the agent's explanation** before the test score: it said a model's error "doesn't scale with" the variance of strength, then that lower variance could lower the error. Corrected: variance sets the predict-the-mean error exactly; a model's error moves only if the removed spread was in panels it gets wrong.
- **Caught a non-actionable recommendation in the agent's memo draft:** "continue only if the next batch is expected to save more than it costs" — nobody can know that in advance. Kept the dollar link but made it computable: a statistical stop (last batch's gain below the check set's ~10% precision) plus a pricing step Kestrel can run on its check set.
- **My questions reshaped the operating plan.** Asking whether "test only the panels it is unsure about" happens while labels are being collected separated one-off, randomly drawn build tests from recurring operating tests, which is where the savings are. Asking what retraining means gave a periodic full retrain, swapped in only if it beats the current model on a random check set. I raised that retraining on panels the model chose to test would bias it: the agent agreed the risk is real (blind spots away from the limit), and I added a random audit sample of production every period.
- **Rejected the agent's suggestion** to drop "consistent with that extract's slightly lower spread of strength" from the test sentence: it is a fact the reader should have, stated beside the number, not used to explain it away. Accepted its audit point to name dev and test explicitly.
- **Extension design and its consequence (mine).** The agent offered a second variant with matched training steps; I kept the brief's recipe (40 passes over 2,000 traces), because a new plant runs the standard recipe on what it has, and stated the confound. All three expectations held, and the result changed the plan: the small-pool frozen network was indistinguishable from a random one at 50–100 panels while fine-tuning was unaffected, so I replaced "frozen early, fine-tune from 250" with fine-tuning from the first batch. My idea of an even lower learning rate below 250 panels was untested, so the memo says only "keep the reduced rate" and lists the rest as a limitation.
- **Asked for a plainer rewrite of the memo**, because the agent's prose was hard to decode. The technical-writing skill from A1 could not be found, so the agent stated and applied explicit rules (one idea per sentence, defined terms, numbered procedures).
- **Changed the agent's process:** it handed me an expectations sheet; I had it ask the questions one at a time so each answer was challenged. My wrong guesses: ridge at 50 labels near 188.9 (got 60.7); the random encoder close to raw ridge (it beat it at every count); the crossover at 250–1,000 (the means crossed at 100–250).
